## Реализованные UI-сценарии

1. Авторизация с невалидным логином и паролем.
2. Отправка формы с пустыми полями.
3. Проверка маскировки пароля.
4. Переход по ссылке "Забыли пароль".

## Helper

Реализован пример helper-метода для создания тестового пользователя напрямую в БД перед тестом.

## API

Реализован пример POST-запроса для создания пользователя.

## Дополнительные сценарии формы авторизации

Дополнительно я бы проверил:

- успешный вход с валидными данными;
- правильный логин и неправильный пароль;
- неправильный логин и правильный пароль;
- пробелы в начале и конце логина;
- чувствительность логина к регистру;
- чувствительность пароля к регистру;
- минимальную и максимальную длину полей;
- специальные символы;
- Unicode в полях;
- отправку формы клавишей Enter;
- корректность сообщений об ошибках;
- несколько последовательных неправильных попыток(rate limit);
- блокировку пользователя;
- SQL Injection;
- XSS;
- CSRF;
- работу сессии после успешного входа;
- logout;
- невозможность использовать старую сессию после logout;
- переход на защищенную страницу без авторизации;
- восстановление пароля существующего пользователя;
- восстановление пароля несуществующего пользователя;
- отсутствие возможности определить существование аккаунта по разным сообщениям ошибок;
- открытие страницы после авторизации;
- работу формы в поддерживаемых браузерах.

## Запуск

Сборка контейнера:
```bash
docker compose up -d
```

Установка зависимостей:
```bash
docker compose exec php composer install
```

Сборка Codeception:
```bash
docker compose exec php php vendor/bin/codecept build
```

Запуск UI-тестов:
```bash
docker compose exec php php vendor/bin/codecept run Acceptance --steps
```

Запуск API-тестов:
```bash
docker compose exec php php vendor/bin/codecept run Api --steps
```
